## Паттерны scope

Анализ публичных scope statements выявляет три паттерна:

### Паттерн 1: По продукту/сервису (доминирующий)
Большинство компаний сертифицируют **конкретный продукт**, а не всю организацию. Примеры:
- AWS — Bedrock, Q Business, Textract отдельно.
- Microsoft — M365 Copilot, Azure AI Foundry, Security Copilot, Copilot Studio, GitHub Copilot — каждый отдельный сертификат с отдельным SoA.
- Google Cloud — Vertex AI, Gemini, Document AI.

**Зачем:** ниже риск audit failure, дешевле первый сертификат, маркетинговая чёткость («наш продукт X сертифицирован»).

### Паттерн 2: По организационной функции
Anthropic — сертифицировал «Claude API + Enterprise» — это не продукт, а блок организационных функций вокруг продукта.

### Паттерн 3: Глобальная структура
KPMG International, BCG — сертифицируют всю организацию глобально. Подходит крупным консалтинговым структурам, у которых AI-инструменты используются кросс-функционально.

### Расширение scope на ресертификации
- Integral Ad Science: initial сертификат на узкий scope → на ресертификации (февраль 2026) добавили «Quality Attention» и «Ad Fraud solutions».
- Microsoft: каждый новый Copilot-продукт получает отдельный сертификат, не пересертифицирует существующие.

## Что это значит для вашей компании

Три вывода:

1. **Узкий scope — норма, а не исключение.** Не пытайтесь сертифицировать всю компанию сразу. Один продукт, одна BU, один регион — стандартный паттерн.

2. **Маркетинговый эффект растёт с количеством сертификатов.** Microsoft получает PR-эффект от каждого нового Copilot-сертификата. Вы можете планировать roadmap: один сертификат в этом году, расширение scope через 2 года.

3. **Окно «первой сотни» закрывается.** К началу 2026 — около 40 компаний. К концу 2026 — оценочно 150–200. К концу 2027 — 500+. После 2027 это перестанет быть маркетинговым отличием.
