> 🇬🇧 [Read in English](../glossary.md) · ⬅ [На главную](./overview.md) · 📖 [Обзор стандарта](./overview.md)

## 1. Базовые концепции ИИ

| Термин | Определение | Источник |
|--------|-------------|----------|
| **AI / искусственный интеллект** | Область исследований и разработки технических систем, порождающих контент, прогнозы, рекомендации, решения для заданного набора человеком целей | 22989 |
| **AI system / система ИИ** | Engineered system that generates outputs (content, forecasts, recommendations, decisions) for a given set of human-defined objectives | 22989 §3.1.4 |
| **AI agent / агент ИИ** | Автоматизированная сущность, которая воспринимает среду и действует для достижения целей | 22989 §3.1.7 |
| **Autonomy / автономность** | Способность системы изменять область использования или цель без внешнего вмешательства | 22989 §3.1.5 |
| **Heteronomy / гетерономность** | Характеристика системы, функционирующей в условиях ограничений, связанных с внешним контролем | 22989 §3.1.16 |
| **AGI / универсальный ИИ** | Тип системы ИИ, покрывающий широкий спектр задач с удовлетворительным уровнем производительности | 22989 |

## 2. Данные и обучение

| Термин | Определение | Источник |
|--------|-------------|----------|
| **Data / данные** | Представление сведений, знаний или инструкций в формализованном виде | 22989 |
| **Training data / обучающие данные** | Набор данных, используемый для обучения модели ИИ | 22989 |
| **Validation data / валидационные данные** | Подмножество для настройки гиперпараметров и предварительной оценки в процессе обучения | 22989 |
| **Test data / тестовые данные** | Данные, не использованные при обучении, для итоговой оценки эффективности | 22989 |
| **Dataset / набор данных** | Организованная коллекция данных для обучения, валидации, тестирования, эксплуатации | 22989 |

| **Ground truth / эталонные данные** | Верифицированные метки или значения, с которыми сравниваются предсказания модели | 22989 |
| **Label / метка** | Значение целевой переменной, сопоставленное с объектом при supervised ML | 22989 |

| Термин | Определение | Источник |
|--------|-------------|----------|
| **Trustworthiness / доверие** | Способность системы выполнять ожидания заинтересованных сторон проверяемым образом | TR 24028 |

| **Explainability / объяснимость** | Степень, в которой механика работы системы может быть представлена в понятных человеку терминах | 22989 |
| **Interpretability / интерпретируемость** | Степень, в которой человек может понять причину решения модели | 22989 |
| **Controllability / управляемость** | Способность человека или другого внешнего агента вмешиваться в функционирование | 22989 |
| **Robustness / робастность** | Способность поддерживать заданный уровень производительности при изменяющихся условиях | TR 24029-1 |
| **Reliability / надёжность** | Способность выполнять требуемые функции при заданных условиях в течение заданного периода | 22989 |
| **Resilience / устойчивость** | Способность восстанавливать требуемый уровень производительности после возмущений | 22989 |
| **Accuracy / точность** | Близость результатов к эталону | TS 4213 |
| **Safety / безопасность функционирования** | Отсутствие неприемлемых рисков для жизни, здоровья, окружающей среды | 22989 |
| **Security / защищённость** | Защита от намеренных атак на КЦД | 22989 |
| **Privacy / приватность** | Защита персональных данных и частной жизни | 22989 |
| **Bias / смещение** | Систематическая ошибка, приводящая к несправедливым результатам; делится на желательное и нежелательное | TR 24027 |
| **Fairness / справедливость** | Свойство системы не создавать несправедливую дискриминацию между группами | 22989 |
| **Accountability / подотчётность** | Возможность определить и привлечь к ответственности сторону за последствия | 22989 |

| **Hallucination / галлюцинация** | Генерация фактически неверного или непроверяемого контента генеративной моделью | 22989/Amd 1 |

## 5. Роли заинтересованных сторон

По ISO/IEC 22989 §5.19:

| Роль | Кто это |
|------|---------|
| **AI stakeholder / заинтересованная сторона** | Лицо или организация, которая может влиять, быть затронутой или воспринимать себя затронутой решением/деятельностью AI-системы |
| **AI provider / поставщик ИИ** | Организация, предоставляющая продукты или услуги ИИ (AI platform provider, AI product or service provider) |
| **AI producer / разработчик ИИ** | Организация, проектирующая, разрабатывающая, тестирующая, развёртывающая продукты или услуги ИИ |
| **AI customer / заказчик ИИ** | Организация или лицо, использующее ИИ-продукт или услугу (AI user и AI deployer) |
| **AI partner / партнёр ИИ** | Организация, поставляющая компоненты системы (API, данные, библиотеки), интеграторы, консультанты |
| **AI subject / субъект ИИ** | Физическое или юридическое лицо, на которое воздействует функционирование системы |
| **AI relevant authority / уполномоченный орган** | Policymaker, регулятор, другие государственные органы |

### Режимы надзора человека

Широко используемые отраслевые термины — их **нет** в ISO/IEC 22989 §5.19. Общее понятие «надзор человека» соответствует ISO/IEC DIS 42105.

| Термин | Значение |
|--------|----------|
| **Human-in-the-loop (HITL)** | Режим, в котором человек обязательно участвует в каждом решении |
| **Human-on-the-loop (HOTL)** | Человек контролирует работу и может вмешаться, но не обязан по каждому решению |
| **Human-in-command (HIC)** | Человек определяет общие правила и цели, имея полномочия остановить систему |
| **Human oversight / надзор человека** | Комплексное понятие, расширяющее controllability; см. ISO/IEC DIS 42105 |

## 6. Жизненный цикл AI-системы

По ISO/IEC 22989 §6, детализировано в ISO/IEC 5338:2023:

| Фаза | Что происходит |
|------|-----------------|
| **Inception / замысел** | Цели, требования, допущения, бизнес-кейс |
| **Design and development / проектирование и разработка** | Архитектура, выбор модели, инженерия признаков, обучение |
| **Verification and validation** | Проверка соответствия требованиям и пригодности для применения |
| **Deployment / развёртывание** | Ввод в эксплуатацию |
| **Operation and monitoring / эксплуатация и мониторинг** | Производительность, детекция дрейфа |
| **Continuous validation / непрерывная валидация** | Повторная оценка при изменениях |
| **Re-evaluation / переоценка** | Полная переоценка при значимых изменениях контекста/данных |
| **Retirement / вывод из эксплуатации** | Прекращение использования с соблюдением требований к данным |

## 10. Гармонизация между фреймворками

### EU AI Act ↔ ISO 22989

| EU AI Act | ISO/IEC 22989 |
|-----------|----------------|
| Provider | AI provider |
| Deployer | AI customer (user/deployer) |
| Importer, distributor | Промежуточные |

### NIST AI RMF ↔ ISO/IEC 42001

| NIST AI RMF | ISO/IEC 42001 |
|-------------|-----------------|
| GOVERN | Clauses 4–5 |
| MAP | Clause 6 + ISO/IEC 42005 |
| MEASURE | ISO/IEC 24029, TS 4213, TR 24027 |
| MANAGE | Clauses 8, 10 + ISO/IEC 23894 |

### High-risk AI / высокорисковая система ИИ

Термин EU AI Act (Annex III). Для него обязателен FRIA (Art. 27), что на практике может реализовываться через ISO/IEC 42005.
